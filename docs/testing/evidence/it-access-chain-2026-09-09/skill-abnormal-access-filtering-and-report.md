# 目标
对公司网络异常访问样本/告警表进行结构化核对与研判：先用低风险过滤口径排除可忽略条目，再对保留的高优先事件归类并生成标准化分析报告。

# 业务规则与口径

## 低风险过滤口径（满足任一条即可过滤）
1. 已知搜索引擎爬虫：源为 Googlebot / Bingbot，且仅访问公开页面（UA 正常）。
2. 已登记白名单设备：源为已登记白名单设备，例如监控探针、供应商维护窗口。
3. 仅端口/DNS 探测：仅做端口或 DNS 探测，且没有任何成功认证或数据交互。
4. 仅命中 404 的 URL 探测：仅命中 404 页面、未触达任何敏感路径的 URL 探测。

每条口径必须同时满足其全部限定条件。例如：仅命中 404 但不属于 URL 探测、或端口探测中存在成功认证尝试，均不可过滤；仅认证失败但属于主动爆破（如 RDP 爆破）也不可过滤。

## 保留事件归类口径
- SSH/RDP 爆破
- 敏感路径访问
- 横向移动
- 敏感文件下载
- 异常登录
- 弱口令/Webshell 特征

# 方法与步骤

## 1. 核对表结构与总行数
- 读表后先确认工作表名、列名与列数；总行数应含表头（例如表头 1 行 + 数据 N 行）。
- 可用于研判的关键字段：序号、时间、源IP、源归属、目标资产、目标端口、事件类型、行为摘要、请求数。

## 2. 逐条按口径核对
- 逐条结合「源归属 / 事件类型 / 行为摘要 / 源IP / 目标资产」字段核对四条过滤口径。
- 记录每条命中的口径与判定依据，输出可过滤序号集合；不满足任何口径的条目进入保留集合。
- 多口径合并时取并集，给出累计可过滤序号集合与保留序号集合。

## 3. 保留事件归类
- 将保留条目按归类口径归入：SSH/RDP 爆破、敏感路径访问、横向移动、敏感文件下载、异常登录、弱口令/Webshell 特征。

## 4. 生成分析报告
- 标题格式：「网络异常访问分析报告（YYYY-MM-DD）」。
- 正文四节：
  - 【1 分析范围与方法】含过滤口径简述
  - 【2 结论概述】保留 N 条需关注事件及类型分布
  - 【3 高优先事件清单】每条保留事件一段：时间｜源IP｜目标资产｜事件类型｜理由｜建议动作
  - 【4 建议措施】
- 只写保留事件，不写已过滤的低风险行。

# 边界条件
- 仅适用于异常访问类样本/告警的过滤与研判，不覆盖其他类型安全数据。
- 过滤口径必须逐条满足全部限定条件，避免因部分特征相似而误判。
- 不编造事件历史中不存在的业务内容，判定需依据表中既有字段。
