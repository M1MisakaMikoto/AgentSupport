# 目标
对「异常访问记录」类日志进行低风险过滤与高危事件归类，产出标准化的网络异常访问分析报告，确保低风险/白名单事件被正确过滤、需关注事件被完整保留并按风险类别归类。

# 业务规则与口径

## 数据字段
异常访问记录包含：序号、时间、源IP、源归属、目标资产、目标端口、事件类型、行为摘要、请求数。

## 过滤口径（按顺序判定，命中即可过滤）
- 口径① 已知搜索引擎爬虫：源归属为 Googlebot / Bingbot，且仅访问公开页面，可过滤。
- 口径② 白名单设备：源 IP 命中白名单（监控探针 192.168.200.5、供应商维护 10.20.0.8），可过滤。
- 口径③ 仅端口/DNS 探测：事件类型为「端口扫描」或「DNS探测」，且无任何成功认证或数据交互，可过滤。
- 口径④ 仅命中 404 的 URL 探测：事件类型为「URL探测」，仅命中 404 页面、未触达任何敏感路径，可过滤。

## 累计口径
- 各口径命中的序号取并集，得到「可过滤集合」。
- 全集减去可过滤集合，得到「保留集合」（需关注/处置的事件）。
- 后续分析只针对保留集合，不分析已过滤事件。

## 保留事件归类
- SSH/RDP爆破：SSH爆破、RDP爆破（多次认证失败，或失败后出现成功登录）。
- 敏感路径访问：访问管理后台/敏感路径且状态码异常（如先 401 后 200）。
- 横向移动：内网多台服务器批量连接（如 445/3389），并用内网账号尝试。
- 敏感文件下载：下载备份/敏感文件且大小或时长异常。
- 异常登录：非白名单地区或异常源 IP 成功登录，并高频读取敏感数据。
- 弱口令/Webshell特征：弱口令尝试、Webshell 特征（如上传伪装文件）。

# 方法与步骤
1. 数据准备与核对：将 xlsx 导出为 UTF-8 CSV，只读确认表头字段与数据行数（统计非表头行）。
2. 定位各口径命中序号：对 CSV 用只读检索（grep/awk）定位符合每条口径的记录，记录其序号。
3. 累计并集：将各口径命中序号合并去重得到「可过滤集合」，全集减去后得到「保留集合」。
4. 归类：将保留集合按上述归类维度分组，并标注关键依据（如认证失败次数、目标路径、数据量、源 IP 归属）。
5. 报告撰写：按下方报告规范产出报告，并回读核对。

## 报告规范
- 标题：网络异常访问分析报告（YYYY-MM-DD）。
- 四节结构：1 分析范围与方法 / 2 结论概述 / 3 高优先事件清单 / 4 建议措施。
- 第 3 节每条一段，含六要素：时间｜源IP｜目标资产｜事件类型｜理由｜建议动作。
- 只写保留集合事件，不写入已过滤事件。

# 边界条件
- 仅覆盖「异常访问」类日志的过滤与报告；不覆盖其他日志类型、威胁情报取证与具体处置操作。
- 过滤口径依赖字段完整性（源归属、源IP、事件类型、行为摘要、目标资产），字段缺失时需人工复核后再判定。
- 白名单 IP 与公开页面范围等具体值随组织资产台账更新，使用前需确认最新名单。
