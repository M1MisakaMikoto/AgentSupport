# 目标
对网络异常访问记录（9 列）逐条做「可过滤 / 保留」判定，输出保留事件清单，并按固定四节结构生成异常访问分析报告。

# 业务规则与口径

## 数据列定义
每条访问记录包含 9 列：序号、时间、源IP、源归属、目标资产、目标端口、事件类型、行为摘要、请求数。

## 四条可过滤口径（各自条件必须全部满足，逐条判定）
1. 搜索引擎爬虫：仅「已知搜索引擎爬虫（Googlebot/Bingbot）且只访问公开页面」才可过滤；若爬虫访问管理后台、敏感路径，必须保留。
2. 白名单 IP：
   - 白名单设备：192.168.200.5（监控探针）、10.20.0.8（供应商维护）。
   - 只有白名单 IP 正在执行其登记行为才可过滤：监控探针＝定时探测；供应商维护＝维护窗口内维护操作。
   - 若白名单 IP 从事 RDP/SSH 爆破、敏感文件下载、弱口令、横向移动等异常行为，必须保留。
   - 判定原则：白名单只豁免「登记行为」，不豁免任何异常行为；同一 IP 按「事件类型 + 行为摘要」逐条判定，不能因 IP 在白名单就整体放行。
3. 端口/DNS 探测：仅「端口/DNS 探测」且「没有任何成功认证或数据交互」才可过滤；探测后出现成功登录/数据交互的必须保留。
4. URL 探测 404：仅「命中 404 且未触达敏感路径」的 URL 探测才可过滤；404 但路径含 /admin、/backup、/upload 等敏感词的必须保留。

## 白名单 IP 出现异常行为的处理
- 必须保留（不得过滤），按普通异常事件同等对待。
- 升级调查：该白名单设备可能已被攻陷、凭证被窃用或被滥用，需单独标记并核查其时间线、登录来源与关联行为。

## 保留事件归类口径
- SSH/RDP 爆破
- 敏感路径访问
- 横向移动
- 敏感文件下载
- 异常登录
- 弱口令 / Webshell 特征

# 方法与步骤

## 1. 数据准备与核对
- 将原始 xlsx 导出为同目录 UTF-8 CSV。
- 用只读方式确认表头为 9 列、数据行数，并列出「序号 + 事件类型」做完整性核对。

## 2. 逐口径过滤判定
- 按四条口径对每条记录逐条判定「可过滤 / 保留」。
- 累计各口径的可过滤集合，得到最终可过滤集合；其余全部保留。
- 白名单 IP 与爬虫必须同时满足「身份 + 行为合规」两个条件；白名单 IP 的异常行为保留并升级调查。

## 3. 保留事件归类
- 将保留事件按归类口径分组，并给出严重程度/优先级与处置建议。
- 示例优先级：Webshell 特征、敏感文件下载、横向移动为最高优先级，需立即隔离排查。

## 4. 报告撰写
- 标题：《网络异常访问分析报告（YYYY-MM-DD）》。
- 固定四节：
  - 【1 分析范围与方法】
  - 【2 结论概述】
  - 【3 高优先事件清单】
  - 【4 建议措施】
- 第三节每条保留事件单独一段，格式固定为「时间｜源IP｜目标资产｜事件类型｜理由｜建议动作」。
- 只写保留事件，不写被过滤事件。
- 报告生成后回读核对：标题、四节结构、保留事件条数、每条字段是否完整。

# 边界条件
- 仅覆盖异常访问日志的过滤判定与报告产出；不覆盖数据源采集、SIEM 平台配置、应急响应处置手册等内容。
- 报告以 docx 形式交付；平台文件引用格式等执行细节不写入报告正文。
