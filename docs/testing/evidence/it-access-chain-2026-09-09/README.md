```text
上传文件 → 逐轮给出口径/样式指导 → 多轮对话完成分析
```

## 2 测试数据与口径（模拟）

- 种子：[abnormal-access-sample.xlsx](../../../../demo/samples/seed/abnormal-access-sample.xlsx)
  （16 行 = 8 条低风险应过滤 + 8 条高优先应保留）
- 模拟低风险过滤口径：
  1. 已知搜索引擎爬虫（Googlebot/Bingbot）且仅访问公开页面；
  2. 源为登记白名单设备：192.168.200.5（监控探针）、10.20.0.8（供应商维护）；
  3. 仅端口/DNS 探测且无任何成功认证或数据交互；
  4. 仅命中 404、未触达敏感路径的 URL 探测。
- 模拟报告样式：标题“网络异常访问分析报告（2026-09-01）”，正文四节：
  【1 分析范围与方法】【2 结论概述】【3 高优先事件清单】【4 建议措施】，
  清单每条一段：时间｜源IP｜目标资产｜事件类型｜理由｜建议动作。

## 3 分环节证据

### 3.2 多轮逐步指导与记忆（S1，共 7 轮）

| 轮 | 内容 | 结果摘录 |
| --- | --- | --- |
| 1 | 读表核对结构/总行数 | “…共 16 条明细” |
| 2 | 给口径①（爬虫） | “符合①的序号：2、5” |
| 3 | 给口径②（白名单） | 结合①②，累计可过滤 2/3/5/6 类集合 |
| 4 | 给口径③（纯探测无认证） | 继续累计（加入 1/4/8 判定） |
| 5 | 给口径④（404-only）+ 出最终结论 | 可过滤 {1..8}，保留 {9..16} 并归类 |
| 6 | **记忆复述（不许重新读文件）** | 完整复述四条口径与保留集（见下方原文） |
| 7 | 给报告样式并生成示范报告 | 生成 `guided-report-s1.docx` 并回读核对 |

第 6 轮原文（记忆核验关键证据）：

> 1. **口径①**：已知搜索引擎爬虫（Googlebot/Bingbot）且仅访问公开页面，可过滤。
> 2. **口径②**：源为已登记白名单设备——192.168.200.5（监控探针）、10.20.0.8（供应商维护窗口），可过滤。
> 3. **口径③**：仅做端口/DNS 探测，且没有任何成功认证或数据交互的条目，可过滤。
> 4. **口径④**：仅命中 404、未触达任何敏感路径的 URL 探测，可过滤。
>
> - 可过滤序号集合：{1, 2, 3, 4, 5, 6, 7, 8}
> - 保留序号集合：{9, 10, 11, 12, 13, 14, 15, 16}
> - SSH/RDP 爆破：9、12；敏感路径访问：10；横向移动：11；敏感文件下载：13；
>   异常登录：14；弱口令/Webshell 特征：15、16

- 产物：`abnormal-access-filtering-and-report`

  `task_done` 0 次、approval/审批 0 次。

## 4 独立核验方法

1. 每轮结束后读取 conversation 事件/最终消息做人工比对；
2. 总结产物用 `/api/skills/{id}` 或容器内 SKILL.md 原文核对章节与关键词；
3. 对 S2 生成 docx 用 python-docx 直接抽取段落做断言（结构、IP 集合、条数），

## 5 结论、边界与真实接入注意点

- 链路能力在本模拟数据上全部通过；多轮记忆、skill 固化业务口径、启用后自动执行均成立。
- 真实 IT 接入前需与 IT 对齐：
  1. 真实导出列名/字段到“口径”的映射；
  2. 白名单与爬虫清单由 IT 给，而不是让 agent 推断；
  3. 报告模板若含表格/LOGO/固定版式，需确认是否超出当前 word 工具能力（当前仅标题+段落）；
  4. 先给脱敏小样复跑本流程，再放大到全量。
