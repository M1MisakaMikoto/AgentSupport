# 上游迁移指南：v0.1 → v0.2

AgentSupport `0.2.0` 是破坏性版本。公共 API 面只保留执行资源（Workspace / Session /
Conversation），业务实体（组织 / 用户 / 项目 / 预设）交由上游自行管理，平台以标签透传。

## 1. 移除的接口

以下路由在 v0.2 中全部移除，请求返回 `404`：

- `/organizations` 全部路由
- `/users` 全部路由
- `/presets` 全部路由
- `/projects` 全部路由（含 `/projects/{id}/preset`、`/projects/{id}/sessions`）

相关错误码同步移除：`PRESET_NOT_OWNED`、`PRESET_DISABLED`、`USER_NOT_FOUND`、
`PROJECT_NOT_FOUND`、`ORGANIZATION_NOT_FOUND`、`PROJECT_HAS_SESSIONS`。

## 2. 标签与执行配置

创建 Session 时通过请求体或网关注入的身份头携带标签，平台不校验存在性：

```http
POST /sessions
X-Tenant-Id: t-1
X-User-Id: u-1
X-Project-Id: p-2

{
  "workspace_id": "ws-1",
  "metadata": { "team": "platform" },
  "config": {
    "skills": [{"skill_id": "review", "enabled": true}],
    "tool_policy": {
      "allowed_tools": ["bash", "task_done"],
      "approval_required_tools": ["bash"]
    }
  }
}
```

- 身份头优先级高于请求体字段；本地开发可只用请求体。
- `metadata` 为任意键值兜底；事件与审计顶层携带 `tenant_id` / `user_id` / `project_id`。
- 执行配置（skills / tools / resources / permissions）随 Session 请求传入，
  替代原 preset 导入；缺省使用部署默认配置。

## 3. auto-create 语义变化

- 仅当调用方显式传入且不存在的 `workspace_id` / `session_id` 时，以该 ID 补建。
- 调用方未传入的字段绝不自动生成：不再有默认 Workspace / 默认用户。
- `parent_conversation_id` 等引用一律严格 `404`。
- 生产建议 `AGENTSUPPORT_AUTO_CREATE_MISSING=false`。
- 拼写错误由上游负责：平台不区分故意补建与拼错，补建通过 `auto_created` 与
  `workspace.created` / `session.created` 事件显式暴露。

## 4. 配置项变化

移除：`AGENTSUPPORT_DEFAULT_WORKSPACE_ID`、`AGENTSUPPORT_DEFAULT_USER_ID`、
`AGENTSUPPORT_AUTO_RESOURCE_NAME`。

新增：`AGENTSUPPORT_RUNNER_TOKEN`（Runner 自注册共享 token，留空则关闭注册）、
`AGENTSUPPORT_RUNNER_HEARTBEAT_TIMEOUT_SECONDS`。

## 5. 数据迁移

`alembic upgrade head`（`20260811_0003`）会自动：

1. 为 `sessions` 增加 `tenant_id` / `user_id` / `metadata` / `config` 列；
2. 从 projects / users / organizations 回填 `user_id` 与 `tenant_id` 标签；
3. 删除 `organizations` / `users` / `presets` / `projects` 表及
   `workspaces.organization_id` 列。

回填无来源的会话标签保持 NULL，计入 `default/unknown` 无头统计。

## 6. 推荐调用流程

```text
POST /workspaces            -> 显式创建工作区
POST /sessions (带标签/config) -> 创建会话
POST /sessions/{id}/conversations -> 提交任务
GET  /conversations/{id}/events(/stream) -> 事件 / SSE
POST /conversations/{id}/input|approval|cancel -> 交互
```

事件消费方应容忍未知事件类型与新增字段，以 `schema_version` 作为演进依据。
